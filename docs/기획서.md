# 전사원 안전교육 QR 출석관리 시스템 — 기획·설계서

> 버전 2.0 · 2026-11-09 · 이 문서는 구현된 소스코드와 1:1로 대응합니다.
>
> **v2 주요 변경 (11장 참고)**: ① 개인별 QR 폐지 → **매주 자동 교체되는 공용 출석 QR** + 직원 본인 휴대폰 자가 출석 ② **교육 자료 파일 첨부** ③ **한솔제지 CI**(파란 그라데이션 상단바, 로고 업로드). 1~8장 중 '개인 QR' 관련 내용은 11장으로 대체됩니다.

---

## 1. 서비스 기획

### 1.1 목적
- 전사원 대상 안전교육의 **참석 확인을 종이 서명부 → QR 스캔**으로 전환하여 입장 대기시간과 집계 업무를 없앤다.
- 관리자는 교육 중에도 **실시간 참석률**을 교대/주전·부서·근무조·직책별로 확인하고, 미참석자를 즉시 파악해 추가 차수를 편성한다.
- 산업안전보건법상 교육 실시 증빙 자료(참석자 명단·시간)를 **엑셀로 즉시 출력**한다.

### 1.2 사용자 및 권한
| 구분 | 설명 | 사용 가능 기능 |
|---|---|---|
| 관리자 (admin) | 안전환경팀 담당자 | 전체 기능: 현황판, 교육·차수, 직원·QR, 엑셀 업·다운로드, 계정관리, 접근기록 |
| 담당자 (staff) | 교육장 입구 출석 확인 요원 | QR 출석체크, 사번/이름 검색 후 참석 처리 **만** 가능 (명단·통계·다운로드 불가) |
| 직원 | 교육 대상자 | 로그인 없음. 본인 QR(인쇄물/사원증 부착/이미지)만 제시 |

### 1.3 핵심 개념: 교육과 차수
- **교육(Training)**: “2026 하반기 전사 정기안전교육”처럼 이수 여부를 판단하는 단위. 대상자 조건(교대/주전·부서·근무조·직책)을 지정할 수 있다(미지정 시 재직 전 직원).
- **차수(Round)**: 같은 교육을 여러 날짜·시간·장소로 나눈 회차(1차, 2차…). 상태 `준비 → 접수중 → 마감`.
- **한 교육 안에서 직원은 1회만 참석 처리**된다. 1차에 참석한 사람이 2차에 다시 스캔하면 “이미 참석(1차 09:03)”으로 표시된다.
- 매월 반복되는 교육은 월별로 별도 ‘교육’을 생성하면 된다.

### 1.4 운영 시나리오
1. **사전 준비 (관리자)**: 직원 명단 엑셀 업로드 → QR 일괄 출력(부서별) 후 배포 → 교육 생성 및 차수 등록 → 담당자 계정 발급.
2. **교육 당일 (담당자)**: 휴대폰으로 로그인 → [QR 출석체크] → 교육/차수 선택 → 카메라로 QR 스캔 → 직원 정보 확인 후 **[참석 처리]**. 인원이 많으면 *연속 자동 처리 모드*로 스캔 즉시 처리.
   - QR 미지참자: 사번/이름 검색 후 처리.
   - 휴대폰 기본 카메라 앱으로 QR을 찍어도 시스템 화면(`/s/{코드}`)이 열려 처리 가능.
3. **교육 중/후 (관리자)**: [현황판]에서 5초 단위 자동 갱신으로 참석률 확인 → 미참석자 명단 확인 → 엑셀 다운로드 → 차수 마감 → 교육 종료.

## 2. 데이터베이스 구조 (PostgreSQL)

```
admins 1 ──< attendance >── 1 employees
                 │
trainings 1 ──< rounds 1 ──< attendance
trainings 1 ──< attendance   (UNIQUE training_id+employee_id → 중복 방지)
admins 1 ──< audit_logs
```

### 2.1 admins — 관리자/담당자 계정
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | SERIAL PK | |
| username | TEXT UNIQUE | 로그인 아이디 |
| password_hash | TEXT | bcrypt 해시 (평문 저장 안 함) |
| name | TEXT | 표시 이름 |
| role | TEXT | `admin` / `staff` |
| failed_count | INT | 연속 로그인 실패 횟수 |
| locked_until | TIMESTAMPTZ | 잠금 해제 시각 (5회 실패 → 10분) |
| last_login_at, created_at | TIMESTAMPTZ | |

### 2.2 employees — 직원
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | SERIAL PK | |
| emp_no | TEXT UNIQUE | 사번 |
| name | TEXT | 이름 |
| shift_type | TEXT | 교대 / 주전 |
| department | TEXT | 부서 |
| work_group | TEXT | 근무조 (A조 등) |
| position | TEXT | 직책 |
| qr_token | TEXT UNIQUE | **QR에 담기는 128bit 무작위 코드** (사번·이름 미포함) |
| active | BOOLEAN | 재직 여부 (퇴사/휴직 시 false → 대상자 집계 제외) |
| created_at, updated_at | TIMESTAMPTZ | |

인덱스: name, department

### 2.3 trainings — 교육
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | SERIAL PK | |
| title | TEXT | 교육명 |
| description | TEXT | 설명 |
| target | JSONB | 대상 조건 예) `{"shift_type":["교대"],"department":["생산1팀"]}` — 빈 객체면 전 직원 |
| status | TEXT | `active`(진행) / `closed`(종료 — 출석 불가) |
| created_at | TIMESTAMPTZ | |

### 2.4 rounds — 교육 차수
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | SERIAL PK | |
| training_id | INT FK → trainings (CASCADE) | |
| round_no | INT | 차수 번호 (UNIQUE training_id+round_no) |
| edu_date | DATE | 교육일자 |
| start_time, end_time | TEXT(HH:MM) | |
| location, instructor | TEXT | 장소, 강사 |
| status | TEXT | `ready`(준비) / `open`(접수중) / `closed`(마감) |

### 2.5 attendance — 참석 기록
| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | SERIAL PK | |
| training_id | INT FK | |
| round_id | INT FK | 참석한 차수 |
| employee_id | INT FK | |
| checked_at | TIMESTAMPTZ | **참석 시간 (서버 시각)** |
| checked_by | INT FK → admins | 처리한 담당자 |
| method | TEXT | `qr` / `manual`(수기) |
| **UNIQUE (training_id, employee_id)** | | DB 레벨 중복 참석 차단 |

인덱스: round_id, (training_id, checked_at DESC)

### 2.6 audit_logs — 접근·작업 기록
| 컬럼 | 설명 |
|---|---|
| admin_id, username | 수행자 |
| action | 로그인, 로그인실패, 직원등록/수정/삭제, 엑셀업로드, 엑셀다운로드, QR출력, QR재발급, 참석취소, 계정생성 등 |
| detail | 상세 내용 |
| ip | 접속 IP |
| created_at | 일시 |

> 스키마는 앱 첫 요청 시 자동 생성(`lib/db.ts`, advisory lock으로 동시 실행 보호)되므로 별도 마이그레이션 작업이 필요 없습니다.

## 3. 화면 구성

| # | 화면 | URL | 권한 | 주요 구성 |
|---|---|---|---|---|
| 1 | 로그인 | `/login` | 공개 | 아이디/비밀번호, 개인정보 처리 안내, 초기설정 안내 |
| 2 | 초기 설정 | `/setup` | 공개(최초 1회) | 설치키 + 최초 관리자 생성. 관리자 1명 이상이면 비활성 |
| 3 | 참석 현황판 | `/dashboard` | 관리자 | 교육 선택 · KPI 4종(대상/참석/미참석/참석률) · 교대주전/부서/근무조/직책별 막대 · 차수별 참석 · 최근 처리 15건 · 대상자 명단(전체/참석/미참석 탭, 검색, 항목 클릭 필터, 수기처리/취소) · 엑셀 다운로드 · 5초 자동갱신 |
| 4 | QR 출석체크 | `/scan` | 관리자·담당자 | 교육/접수중 차수 선택 · 카메라 스캐너 · 연속 자동 처리 모드 · 사번/이름 검색 · 직원 카드(참석/중복/대상아님 색상 구분) · 진동/효과음 · 기기별 처리 내역 |
| 5 | QR 직접 접속 | `/s/{코드}` | 관리자·담당자 | 휴대폰 기본 카메라로 QR을 찍었을 때 열리는 확인·처리 화면 |
| 6 | 교육·차수 관리 | `/trainings` | 관리자 | 교육 목록(대상·참석률), 교육 생성/수정(대상 조건 선택), 차수 추가/수정/삭제, 차수 상태 전환, 교육 종료/재개/삭제 |
| 7 | 직원·QR 관리 | `/employees` | 관리자 | 필터(검색·교대주전·부서·근무조·직책·재직), 직원 등록/수정/삭제, 일괄 활성/비활성/삭제, 엑셀 양식 다운로드·업로드, 개별 QR 보기·PNG 저장·재발급 |
| 8 | QR 일괄 출력 | `/employees/print` | 관리자 | 필터/선택된 직원 QR 카드 A4 인쇄(PDF 저장) |
| 9 | 계정 관리 | `/admins` | 관리자 | 계정 추가, 권한 변경, 비밀번호 초기화, 잠금 해제, 삭제 |
| 10 | 접근 기록 | `/logs` | 관리자 | 감사 로그 조회·검색 |
| 11 | 내 계정 | `/account` | 전체 | 비밀번호 변경 |

모든 화면은 반응형(모바일 우선)이며, 휴대폰에서 상단 메뉴는 가로 스크롤 탭으로 표시됩니다.

## 4. 기능 명세서

### 4.1 인증·계정
| ID | 기능 | 상세 |
|---|---|---|
| AUTH-01 | 로그인 | bcrypt 검증 → HS256 서명 JWT를 httpOnly·Secure·SameSite=Lax 쿠키로 발급(10시간) |
| AUTH-02 | 로그인 잠금 | 5회 연속 실패 시 10분 잠금, 관리자가 즉시 해제 가능. 존재하지 않는 계정도 동일 응답시간·메시지(계정 존재 여부 노출 방지) |
| AUTH-03 | 세션 검증 | 모든 요청마다 쿠키 검증 + DB 계정 재조회 → 삭제·권한변경 즉시 반영 |
| AUTH-04 | 권한 분리 | API 단위로 admin/staff 검사(403), 관리자 화면은 서버 레이아웃에서 차단 |
| AUTH-05 | 최초 설정 | 관리자 0명일 때만 `/setup`에서 `SETUP_KEY` 확인 후 생성 |
| AUTH-06 | 계정 관리 | 생성/권한변경/비밀번호 초기화/삭제 (본인 삭제·본인 강등 방지) |

### 4.2 직원·QR
| ID | 기능 | 상세 |
|---|---|---|
| EMP-01 | 직원 등록/수정 | 사번·이름 필수, 사번 중복 검사, 교대/주전 값 정규화(주간·일근 → 주전) |
| EMP-02 | 엑셀 업로드 | .xlsx ≤10MB, 상위 10행에서 헤더 자동 탐색(사번/사원번호, 이름/성명, 근무형태 등 별칭 인식). 사번 기준 **업서트**: 신규 등록, 기존 갱신(**QR 유지**). 행별 오류 리포트. 옵션: 파일에 없는 직원 일괄 비활성(전체 명단 갱신) |
| EMP-03 | 양식 다운로드 | 헤더+예시+작성안내 시트 |
| EMP-04 | QR 자동 생성 | 등록 즉시 128bit 무작위 토큰 생성. QR 내용 = `https://도메인/s/{토큰}` |
| EMP-05 | QR 보기/저장 | 모달에서 확대 표시, PNG 저장 |
| EMP-06 | QR 재발급 | 분실 시 새 토큰 발급 → **기존 QR 즉시 무효** |
| EMP-07 | QR 일괄 출력 | 필터/선택 직원 카드형 A4 인쇄 (이름·사번·부서·근무조) |
| EMP-08 | 퇴사 처리 | 비활성화(기록 보존, 대상자 제외) 또는 삭제(참석기록 포함 삭제) |

### 4.3 교육·차수
| ID | 기능 | 상세 |
|---|---|---|
| TRN-01 | 교육 생성 | 교육명·설명·대상조건·초기 차수 목록 |
| TRN-02 | 대상 조건 | 교대/주전·부서·근무조·직책 다중 선택 (AND 조건, 항목 내 OR) |
| TRN-03 | 차수 관리 | 추가/수정, 상태 준비·접수중·마감. 참석기록이 있는 차수는 삭제 불가 |
| TRN-04 | 교육 종료 | 종료 시 담당자 화면에서 숨김·출석 불가, 재개 가능 |
| TRN-05 | 교육 삭제 | ‘삭제’ 문자 입력 확인 후 참석기록 포함 삭제 |

### 4.4 출석 처리
| ID | 기능 | 상세 |
|---|---|---|
| ATT-01 | QR 스캔 | html5-qrcode 후면 카메라, 12fps. 시스템 URL/토큰 외 QR은 거부 |
| ATT-02 | 직원 정보 표시 | 이름·사번·교대주전·부서·근무조·직책, 기존 참석 여부·시각·처리자 |
| ATT-03 | 참석 처리 | 버튼 클릭 → 서버시각으로 저장, 처리자·방식(QR/수기) 기록 |
| ATT-04 | **중복 방지** | ① DB `UNIQUE(training_id, employee_id)` + `ON CONFLICT DO NOTHING` (동시 8건 요청 테스트 → 1건만 성공) ② 화면에서 “이미 참석 처리됨 (n차 hh:mm:ss)” 노란 경고 + 경고음 ③ 같은 QR 3초 내 재인식 무시 |
| ATT-05 | 검증 | 종료된 교육, 접수중이 아닌 차수, 비활성 직원, 대상 외 직원 → 처리 거부 및 사유 표시 |
| ATT-06 | 연속 자동 처리 | 스캔 즉시 처리 후 1.8초 뒤 다음 스캔 대기 (대규모 입장용) |
| ATT-07 | 수동 검색 | 사번/이름(2자 이상)으로 조회 후 처리 |
| ATT-08 | 수기처리/취소 | 관리자가 현황판 명단에서 수기 참석 또는 참석 취소(감사로그 기록) |
| ATT-09 | 피드백 | 성공: 초록 배너+짧은 비프+진동, 중복/오류: 노랑/빨강 배너+낮은 경고음+긴 진동 |

### 4.5 현황·통계·다운로드
| ID | 기능 | 상세 |
|---|---|---|
| DSH-01 | KPI | 대상자 수, 참석자 수, 미참석자 수, 참석률(소수 1자리) |
| DSH-02 | 구분별 현황 | 교대/주전별, 부서별, 근무조별, 직책별 — 대상/참석/참석률 막대 |
| DSH-03 | 차수별 현황 | 차수별 일시·장소·상태·참석 인원 |

## 8. Vercel 배포 가이드

1. GitHub에 이 프로젝트를 올립니다 (`safety-edu` 폴더가 저장소 루트).
2. [vercel.com](https://vercel.com) → **Add New → Project** → 저장소 Import (Framework: Next.js 자동 인식).
3. 프로젝트 → **Storage → Create Database → Neon (Postgres)** → 프로젝트에 Connect.
   → `DATABASE_URL` 환경변수가 자동 등록됩니다.
4. **Settings → Environment Variables** 에 추가:
   - `AUTH_SECRET` : 32자 이상 임의 문자열 (예: `openssl rand -base64 48` 결과)
   - `SETUP_KEY` : 최초 관리자 생성용 비밀 문구
5. **Deployments → Redeploy** (환경변수 반영).
6. `https://<프로젝트>.vercel.app/setup` 접속 → 설치 키 입력 후 관리자 계정 생성.
7. [직원·QR] 양식 다운로드 → 명단 작성 → 업로드 → QR 일괄 출력·배포.
8. [교육·차수] 교육 생성 → [계정관리] 담당자 계정 발급 → 교육 당일 담당자 휴대폰으로 `/scan` 사용.

> ⚠ QR에는 접속 도메인이 들어가므로 **운영 도메인을 확정한 뒤 QR을 출력**하세요. 도메인이 바뀌어도 앱 내 스캐너(`/scan`)는 코드 부분만 읽어 계속 동작하지만, 휴대폰 기본 카메라 연결은 새 도메인으로 재출력해야 합니다.

### 향후 확장 아이디어
- SSO(사내 AD/OAuth) 연동, 직원 본인 이수내역 조회 페이지
- 교육 자료/서명 이미지 첨부, 미참석자 문자·메일 알림
- 사원증 바코드(기존 카드) 인식 지원

| 항목 | 내용 |

## 13. v2.2 변경: 관리감독자 출석 인정

관리감독자는 법적으로 본 교육 이수 의무가 없으므로 **모든 교육에서 항상 '출석(인정)'** 으로 처리한다.

| 항목 | 내용 |
|---|---|
| 지정 | [직원관리] 직원 수정 → 관리감독자 '예', 또는 엑셀 **관리감독자** 열에 `Y`(○, 예, 1 등 인식) |
| 엑셀 재업로드 | 관리감독자 열이 **있으면** 그 값으로 갱신, **없으면** 기존 지정 유지 |
| 집계 | 교육 대상자이면 실제 출석 여부와 무관하게 **참석 인원·참석률에 포함**, 미참석 명단에서 제외 |
| 실제 출석 | QR/수기로 출석하면 실제 출석시간도 기록됨. 교육 대상 조건(교대/부서 등)과 관계없이 항상 출석 가능 |
| 현황판 | 참석 KPI에 "관리감독자 출석인정 N명 포함" 표시, 명단에 [관리감독자] 탭·배지, 미출석 시 '출석인정' 표시 |
| 엑셀 다운로드 | 요약에 출석인정 인원 주석, 명단 '비고' 열에 `관리감독자(출석인정)` / `관리감독자` |
| DB | `employees.is_supervisor BOOLEAN DEFAULT false` (자동 추가) |

## 14. v2.3 변경: 회사 보유 엑셀 그대로 업로드

| 항목 | 내용 |
|---|---|
| 흐름 | [직원관리 → 엑셀 업로드] 파일 선택 → **자동 분석·미리보기** → (필요 시 열 수정) → [N행 등록하기] |
| 시트 | 여러 시트 중 직원 명단으로 보이는 시트를 자동 선택, 변경 가능 |
| 제목(헤더) 행 | 상위 30행에서 자동 탐색 (병합된 제목·작성일 줄 등 무시), 행 번호 직접 변경 가능 |
| 열 자동 매칭 | 사번(사원번호·직원번호·개인번호·직번), 성명(이름·사원명), 구분(교대/주전·근무형태), 부서(소속·팀), 근무조(조·반), 직책(직위·직급), 관리감독자 — 열 순서 무관, 드롭다운으로 수정 가능 |
| 미리보기 | 지정한 열로 읽은 첫 5명 + 전체 인원 수 (합계·빈 줄 제외) |
| 건너뛰는 행 | 사번·성명이 모두 빈 행(합계, 구분선, 빈 줄) |
| 기존값 보호 | 파일에 없는(지정 안 한) 열은 기존 직원 정보를 지우지 않고 유지 |
| 파일 형식 | .xlsx / .xlsm / .csv(UTF-8·EUC-KR 자동 인식). 구형 .xls 는 .xlsx 로 저장 후 업로드 안내 |
